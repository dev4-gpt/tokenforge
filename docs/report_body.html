TokenForge

Six agents on Luminal rewrite the hottest function of a small LLM that runs on this laptop. A harness they cannot change keeps a kernel only if the model's output stays byte-identical, then times it. MongoDB Atlas stores every attempt so the next round can learn from it.

Fresh tests, run once

Geometric-mean speedup over stock llama2.c on a model and prompts that were never used while the agents optimized.

1 · PROPOSE

Six agents, in parallel

DeepSeek-V4.1-Flash on Luminal. Three run with thinking off ("fast"), three with low reasoning ("reasoner"). Each gets a different strategy hint plus memories retrieved from Atlas.

2 · TEST

A referee they can't touch

Same clang -O3 flags, unsafe code rejected, no network. Output must match the original byte for byte. Then a warm-up and the median of 5 timed runs.

3 · LEARN

Memory in MongoDB Atlas

Every attempt is stored with an on-device embedding. A new champion must beat the old one by 5% on the 15M model and also win on the 42M model.

Limits

    
    
      
  • One laptop (Apple M3 Pro, 12 cores) with other apps running. We report medians and ranges.

  • Only matmul was optimized; the rest of llama2.c is unmodified upstream code (MIT).

  • No Accelerate or BLAS is linked, so the claim is faster than stock llama2.c, not faster than BLAS.

  • The DeepSeek weights do not change. What improves is the kernel and the team's memory.
